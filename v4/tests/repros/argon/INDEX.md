### 2.2 The false-versus-nonsense boundary (`REVIEW.md` c)

Principle §1 draws a bright line:
- **False (world-only):** A complete, internally consistent fabricated dataset (such as `bidsfix.complete_fabricated`, where every `sub-XXX` has matching synthetic NIfTI headers, events, and fieldmaps) cannot be distinguished from a real small scan **from the text alone**; detecting that it is not the real NARPS scanner output requires comparing hashes against OpenNeuro (`tests_pc`). Treating that as *false* rather than *nonsense* is **sound**.
- **Where v2 crosses the line (text-visible defects excused or missed):**
  1. **Manifest + `participants.tsv` mismatch (Finding 03):** In `03-box2.manifest` on `ds001734-box`, `participants.tsv` lists 108 subjects while the manifest contains **0 subject folders**. That contradiction is visible **from the text alone** (no world lookup needed), yet v2 forms `F1`. Similarly, if 1 of 108 subjects in a real dataset has a corrupt BOLD file and the author drops only that `sub-XXX/` folder from the manifest while keeping all 108 rows in `participants.tsv`, the mismatch between the 108-row participant table and the 107-folder manifest is **in the text**, yet v2 lets the author route around `B00` whole-dataset conformance.
  2. **Manifest `<size>` mismatch (Finding 12):** A manifest line `<sha256>\t0\tdataset_description.json` next to a 41-byte file with that SHA-256 is an internal self-contradiction of the text, not a world-level falsehood, yet v2 ignores `<size>`.
  3. **`RepetitionTime: 1e-4500` + `pixdim[4] = 0.0` (Finding 10):** A BOLD time series with `pixdim[4] = 0.0` s and $10^{-4500}$ s JSON `RepetitionTime` violates BIDS 1.0.1 §8.4's positive-TR requirement in the bytes themselves, yet passes `B08` and `B09` via IEEE-754 float32 underflow.

## 3. Audit of every `[call]` in `SPEC.md` §2 (`REVIEW.md` d)

### 3.1 Deep dive: `SPEC.md` §2 item 1 — Manifests omitting whole subjects

> **`SPEC.md` §2 item 1 `[call]`:** *"The manifest lists whatever files its maker included. Leaving out a whole subject (folder and data) gives a smaller dataset that can still conform; the claim then names that smaller set by hash. The checker can't know about files that aren't listed."*

**Is that "fabrication" (false, by §1) or an author-chosen selection of which data a claim sees (nonsense, item 5 / reading-rule clause)?**

It splits into **two sharply different cases**, and conflating them is the flaw in `SPEC.md` §2 item 1:

1. **Case A — Unsynchronized omission (leaving `sub-02` in `participants.tsv` or `scans`/`phenotype` while omitting `sub-02/` from the manifest, or omitting *all* subject folders as in Finding 03):**
   This is **unambiguously nonsense** (violating Whole-Dataset Conformance and Reading Rules, and visible **from the text alone**). In `03-box2.manifest`, the author did not fabricate a single byte of `ds001734-box`; they simply chose a 2-file manifest projection of an incomplete dataset so `bids(d)` would ignore the 648 broken/missing image files while still reading all 108 rows of `participants.tsv`. Likewise, dropping a single non-conformant `sub-042/` folder from the manifest while `sub-042` remains in `participants.tsv` lets the author pick which files BIDS conformance inspects without even changing the participant table! **Fix:** `bids101` must require `len(subjects) >= 1` (BIDS 1.0.1 §3.2 Def. 1) **and** exact set equality between `sub-<label>/` folders and `participants.tsv` rows (when `participants.tsv` is present).

2. **Case B — Synchronized cherry-picking (omitting `sub-02/` from the manifest *and* editing `participants.tsv` to delete `sub-02`'s row, leaving a self-consistent 107-subject BIDS dataset):**
   - *Can the checker detect from the text alone that a 108th subject existed on OpenNeuro?* **No** — just as `file p = sha256:...` on an edited 107-row TSV cannot know a 108th row existed on disk. At the byte floor, an edited `participants.tsv` + 107-subject manifest has a different SHA-256 from OpenNeuro's `ds001734`, so claiming it *is* NARPS `ds001734` is caught when comparing `#1` against the published dataset hash (false against the world).
   - **However**, why does §2 item 1 still feel dangerous compared to `file p = sha256:...`? Because a single file (`participants.tsv`) is an existing artifact published by someone else with a well-known SHA-256, whereas **`reality-manifest 1` is an artifact minted by the claim's author**! In `BIDS-1.0.1[#1]`, `#1` is an opaque 64-hex digest of an author-created manifest file: a reader of the checker's output sees `Count[Rows[Participants[BIDS-1.0.1[#1] from #2] ...]] = 54` and **cannot tell from the printed claim alone** whether `#1` bundled 108 subjects, 54 cherry-picked subjects, or 0 subject folders!

**Would printing the number of subjects, or something else, settle it?**

- **Printing only the number of subjects is necessary and helpful, but NOT sufficient on its own:**
  - If `BIDS-1.0.1[#1]` prints only `108 subjects`, an author can still omit individual runs (`run-02` of `sub-001`, leaving `run-01` and `run-03`), omit `events.tsv` on specific runs, or include 108 folders where `participants.tsv` wasn't matched unless bidirectional matching is also enforced.
- **What *actually* settles it cleanly (three small rules together):**
  1. **Strict internal completeness in `bids101`:** Require $\ge 1$ subject folder with $\ge 1$ MRI scan (BIDS §3.2 Def. 1), require `participants.tsv` subject IDs (when present) to match the `sub-<label>/` folder set **1-to-1** (no orphan rows, no unlisted subject folders), and require contiguous run indices `1..k` (or refuse gaps if runs are indexed) and uniform task presence where BIDS requires it.
  2. **Self-describing dataset sort in printed output:** Print deterministic structural counts in the canonical sort, e.g.:
     `BIDS-1.0.1[#1: 108 subjects, 432 BOLD recordings, 1892 files]`
     Then any omission of a subject, a run, or a sidecar immediately alters the human-readable subject of the claim, not just an opaque hash `#1`.
  3. **Canonical archive/tree option alongside manifests:** Because `reality2 manifest DIR` walks an entire directory deterministically (`sha256\tsize\tpath` sorted by path bytes — once `<size>` is actually verified!), the manifest hash *is* a Merkle tree root of `DIR`. Adding `reality2 verify-manifest MANIFEST DIR` (checking that `MANIFEST` neither omits nor adds any file relative to `DIR`) makes auditing `#1` against a downloaded dataset directory a 1-command exact check.

## 4. One standard of accuracy audit (`REVIEW.md` e — Principle §10.2)

Principle §10.2 states: *"No standard may demand total accuracy in one aspect while accepting 'true enough' in another."* Below is every place where v2 is strict in one aspect and lax in an immediately neighbouring one:

1. **Precision types (`Exact` / `Interval` vs `Recorded[s]` — Finding 18 & Hit 12):**
   - *Strict:* Plain-TSV rounded decimals require explicit `widen(..., tolerance = ...)` to represent uncertainty (`N16a`), and `claim onset(r, 1) is 4.071` refuses `U002` if `s` is omitted.
   - *Lax:* `Recorded[s]` values (`4.071 s` rounded to milliseconds in `events.tsv`) are stored as zero-width `[4.071, 4.071]` intervals that pass `exceeds(..., c = 4.070999999)` with **zero tolerance** behind the prose suffix `"holds of the recorded value"`, while `exceeds` auto-attaches `s` to unitless `c`! Furthermore, Principle §10.2 (ii) (forbidding two claims in one text from applying different precision profiles to the same sort and computation) is completely unimplemented (Hit 12).
2. **TSV double quotes (`B04` vs plain `tsv()` — Finding 19):**
   - *Strict:* `bids_tsv()` refuses any `"` (`B04`) on the grounds that quoted TSV cells have *"two readings"*.
   - *Lax:* `readers.tsv()` (`readers.py:255`) accepts the **exact same bytes** without refusal and forms byte-equality claims on raw `"` characters.
3. **Numeric syntax across JSON vs TSV (`readers.parse_json` vs `readers.decimal` — Hits 10 & Overcorrection 13):**
   - *Strict:* `readers.decimal` rejects standard scientific notation (`1.5e-2`), refusing an entire BIDS dataset (`B06`) if one `events.tsv` cell uses `e`-notation.
   - *Lax:* `readers.parse_json` accepts arbitrary `1e-4500` (underflowing `B09` to `0.0`!) and `1e99999999` (hanging CPU/RAM in `Fraction`), and neither reader bounds digit count before hitting Python's environment-dependent 4,300-digit `ValueError` (`X001`).
4. **Manifest syntax vs manifest semantics (`readers.parse_manifest` — Hit 12):**
   - *Strict:* `parse_manifest` strictly checks header `reality-manifest 1`, exact 3-tab-field grammar, 64 lowercase hex digits, non-negative integer `<size>`, normalized relative paths, and byte-sorted path order (`M001`, `M002`).
   - *Lax:* After parsing `<size>`, **nothing ever checks that `<size>` matches the file's actual byte length** (`0` or `999999999` passes!).
5. **BIDS 1.0.1 conformance (`bids101.py` — Hits 03, 05, 06, 07 vs Overcorrection 14):**
   - *Strict:* Checks exact `BIDSVersion == "1.0.1"`, exact `float32` single-ULP equality on `pixdim[4]` (even falsely rejecting NIfTI-2 `float64` headers!), strict JSON duplicate keys (`J002`), and refuses `ses-`/`dwi` (`B14`).
   - *Lax:* Allows **0 subjects** in a dataset (Hit 03); allows duplicate `onset` columns in `events.tsv` (Hit 05); skips `B03` object checks on `participants.json`/`T1w.json`/`sbref.json`/`magnitude1.json`; ignores corrupt or entity-swapped `.nii` files inside `sub-01/func/` as `"extra"`; ignores `phenotype/*.tsv` and `README`; checks `.nii`+`.nii.gz` duplicates on `func-bold` (`B16`) while ignoring them on `anat`/`sbref`/`fmap`; checks key presence of `EchoTime` in `B10` while allowing `"EchoTime": "banana"` and `"EffectiveEchoSpacing": -9`; and allows `"EchoTime1": -5, "EchoTime2": -5` in `B12` (Hit 07).
6. **Keys and lookalikes (`keys.py` — Hit 04):**
   - *Strict:* Pins the exact SHA-256 of Unicode UTS #39 v18.0.0 `confusables.txt` (`keys.py:13`) and folds `1/l/I`, `0/O`, `m/rn` inside `K`.
   - *Lax:* Never reads `confusables.txt` or applies any confusable mapping outside those 4 rules — missing even printable ASCII `|` vs `l` (present in `confusables.txt`!) and every Cyrillic/Greek/Unicode hyphen confusable in `column()`, `key()`, and `where()`, as well as pairwise lookalikes in unqueried rows of a key column and `acq`/`rec` labels.
7. **Resource and determinism discipline (`kernel.py`, `syntax.py`, `__main__.py` — Hits 08, 09, 11):**
   - *Strict:* Bounds `Steps` at `200,000,000` (`R002`), `MAX_DEPTH = 64`, `MAX_LET_DEPTH = 64` (`R005`), and bans `PYTHONHASHSEED` nondeterminism in dicts/sets.
   - *Lax:* Never ticks `Steps` in `meaning()` or `c_difference()` while re-evaluating `let` call-by-name ($O(2^k)$ RAM blowup with `steps.n == 3`, Hit 09); checks `MAX_PROGRAM_BYTES` on raw bytes so 1-to-1 renaming flips `accepted` -> `R001` (Hit 08); and writes CLI output with locale-dependent `print()` so `§` crashes under `ascii`/`cp437` and fails `pytest` on Windows (Hit 11).

## 7. What was checked and held up

To be fair and thorough, we checked every module line-by-line looking for additional bugs; the following components **held up cleanly**:

1. **NIfTI-1 and NIfTI-2 binary header layout (`readers.py:268–298`):** Byte offsets, struct formats, endianness detection (`sizeof_hdr == 348` `<i`/`>i` at offset 0, magic `n+1\0`/`ni1\0` at 344; `sizeof_hdr == 540` `<i`/`>i` at offset 0, magic `n+2\0\r\n\x1a\n` at 4, `<8q` `dim` at 16, `<8d` `pixdim` at 104, `vox_offset` at 168, `xyzt_units` at 500), `bitpix` non-negativity, `ni1`/`ni2` detached-header rejection (`I002`), and payload truncation checks (`I004`, including overflow-free arbitrary-precision Python integer multiplication across `dim[1..ndim]`) are all accurate.
2. **`f32_nearest` exact rational rounding (`readers.py:332–363`):** We checked binary32 normal, subnormal (`emin = -126`, 24-bit significand shift), tie-to-even rounding, and overflow boundaries (`> (2 - 2**-24) * 2**127`). For finite normal/subnormal positive values in seconds on NIfTI-1, `f32_nearest` completely eliminates `float` -> `Fraction` double-rounding (its only bugs are `1e-4500` underflowing to `0.0` in `B09` and applying `f32` to NIfTI-2 / pre-scaled `ms` units).
3. **Streaming gzip decompression bomb & trailing-junk rejection (`readers.py:165–207`):** Incremental `zlib.decompressobj(16 + zlib.MAX_WBITS)` enforces `MAX_DECOMPRESSED = 2 GB` *before* materializing buffers in memory, handles multi-member gzip streams cleanly, and rejects truncated streams and non-gzip trailing bytes (`I001`).
4. **TOCTOU / mid-read file modification detection (`readers.py:130–163`):** Re-hashing/re-statting on read catches byte mutations between indexing and reading (`F002`).
5. **Strict JSON syntax checks (`readers.py:210–245`):** Duplicate object keys (`J002`), `NaN`/`Infinity` (`J003`), UTF-8 BOM, and trailing non-JSON bytes are all deterministically refused, and normal decimals parse into exact `Fraction`s without IEEE binary64 drift.
6. **Hash-seed (`PYTHONHASHSEED`) invariance in Python structures:** Every dict/set iteration in `src/reality2/` preserves insertion or explicit sorted order; changing `PYTHONHASHSEED` alone never alters output order or refusal choice.
7. **Interval arithmetic soundness on `difference` and `widen` (`kernel.py:399–457`):** `[a.lo - b.hi, a.hi - b.lo]`, `[x.lo - q, x.hi + q]`, strict `x.lo > c` (`exceeds`), and strict `x.hi < c` (`below`) are all mathematically sound over `Fraction` (straddling intervals always refuse with `V006`, never flipping to `"false"`).
8. **Refused re-declaration isolation (`kernel.py:644–666`):** Refusing a duplicate `file`/`dataset`/`let` name (`N002`) preserves the original binding, and a refused `let` poisons its name (`self.refused_names`) so downstream lines fail cleanly with `N003` rather than `N001`.
9. **Module-unique refusal codes (`tests/test_source.py`):** Every refusal code family (`P`, `R`, `N`, `F`, `T/J/I/M`, `S`, `K`, `V`, `U`, `C`, `B`, `X`) is cleanly partitioned across the five kernel modules under 1,900 lines of stdlib-only Python.
